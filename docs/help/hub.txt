name: HUB
kind: command

Browse and install applications from the mmcore package hub.

HUB
HUB LIST
HUB INSTALL id$
HUB UPDATE
HUB REMOVE id$
HUB FETCH relpath$

`HUB` on its own opens the full-screen hub: a pixel-art browser with a
loading screen, a category listing and a detail page. The text forms below
keep working in programs and scripts.

The loading screen shows the hub cube and one progress bar while it connects,
downloads the index and fetches the first icons. If it cannot load, the bar
turns red and one red line names the reason (OFFLINE, SERVER ERROR n or
UNSUPPORTED INDEX). Press Enter to retry or Esc to leave.

The listing shows `ALL` and every non-empty category as tabs. Each row has the
app icon, title, summary, author, size and a state badge: `INSTALLED` (lime),
`UPDATE` (orange) or `NEEDS v<minver>` (red). Apps that need a newer mmcore are
shown greyed but can still be selected. In a wide window the selected app's
summary, version, author and picture appear in a preview panel on the right;
in a narrow window the selected row expands to show them inline. The picture
is the optional hero (info/<id>/HERO.PNG), otherwise the first screenshot,
otherwise the thumbnail. It loads in the background, so the list stays
responsive.

The detail page has no header. The large picture and its thumbnail strip are
the screenshots. When the index has a hero it is framed at the top of the
right column (full width, 16:9), with the title in the text font above the
info row. With no hero that corner is the large title and icon. Then one info
row (author, version, size, category). Empty fields are left out. The
description sits under that row. `about` is either that text or a path such
as info/<id>/about.txt, which is loaded in the background. A WHAT'S NEW
section is shown only when the index entry carries the text of
INFO/CHANGES.TXT (or a path to that text). There is one main button: `INSTALL`, `UPDATE`, `RUN`
or a greyed `NEEDS v<minver>` when the device is too old. The install dialog
shows the download progress and can be cancelled with Esc or its CANCEL
button. When the package is in place it shows DONE with a RUN button: Enter
or RUN starts the app, Esc goes back. RUN leaves the hub and starts the
installed app exactly like the APPS launcher.

Controls:

- Listing: Up/Down select, PgUp/PgDn page, Home/End jump, Left/Right change
  category tab, Enter opens the detail page, Del removes an installed app,
  Esc leaves the hub. Typing a letter jumps to the next title that starts with
  it.
- Detail: Left/Right change screenshot, Up/Down and PgUp/PgDn scroll the about
  text, Enter presses the main button (INSTALL, UPDATE or RUN), Del removes,
  and Esc returns to the listing with the same tab and selection.
- Remove: Del asks `REMOVE <TITLE>?` with YES/NO buttons. Y removes, N
  cancels, Enter picks the focused button (default NO) and Esc cancels.
- Mouse: click a tab or a row, click the selected row again to open it, wheel
  scrolls the list or the about text, click a thumbnail to switch screenshots,
  click the main button, and click outside a dialog to cancel it.

The hub reads an index from `OPTION HUB URL` (default
https://hub.mmcore.dev/) and installs `.APP` packages into `C:/APPS/` when
that folder exists (A: is the ramdisk and is lost at power-off), otherwise
into the first writable directory on ~OPTION~ PATH (by default `A:/APPS/`).
With the default PATH, `C:/APPS/` is also searched first, so installed apps
show up in ~APPS~ and run by name. An app that is already installed is
updated in place, wherever it lives, and is listed once. The index lists each package's id, version, size
and SHA-256 checksum. Downloads are checked against both before anything is
written, so a corrupt or tampered package is rejected instead of installed.

HUB LIST prints one line per package: id, version, and state
(NOT INSTALLED, INSTALLED, UPDATE or NEEDS NEWER). INSTALLED means the
package is already present; UPDATE means the index carries a newer version
than the installed `PACKAGE.INF`. NEEDS NEWER means the package asks for a
newer mmcore (`minver`) than this build.

HUB INSTALL "id" downloads and installs (or updates) one package. Progress is
printed while it runs. Failures are ordinary catchable BASIC errors whose text
is one of:

    OFFLINE               no network, DNS or usable TLS
    SERVER ERROR n        the server answered with HTTP status n
    UNSUPPORTED INDEX     the index is not schema 1 (a newer mmcore may help)
    CHECKSUM FAILED       size or SHA-256 did not match the index
    NEEDS MMCORE x.y.z    the package needs a newer mmcore
    NO WRITABLE APP FOLDER  no PATH directory can be written
    NOT FOUND / NOT INSTALLED / REMOVE FAILED / WRITE FAILED / CANCELLED

HUB UPDATE installs every package whose state is UPDATE. HUB REMOVE "id"
deletes the installed `.APP` and recomputes its state. HUB FETCH "path"
downloads one asset relative to the hub root (used for icons, heroes,
thumbnails and screenshots) and prints its byte count; an empty path makes
no request. Repeated fetches of the same path come from the hub's cache.

Installed packages are found by scanning every PATH directory for
`<id>.APP` (case-insensitive) and by matching the `name` field in a package's
`PACKAGE.INF`. A package installed this way runs with its bare name, exactly
like any other PATH app; see ~APPS~.

Example:

    OPTION HUB URL "https://hub.mmcore.dev/"
    HUB LIST
    HUB INSTALL "jetpack"
    JETPACK
    HUB UPDATE
    HUB REMOVE "jetpack"
